Components · How to read this page

Conventions

Tokens only

Specs name role tokens (--accent, --fg-muted) and Tailwind utilities from the theme. Raw hex values never appear in component code.

States

Every interactive component defines rest, hover, focus-visible, pressed, disabled and, where it applies, loading, error, selected and empty.

Phone

Phone layouts are not designed yet. "Below 900px" notes are the interim rule: stack in reading order, keep tokens, full-width actions.

Themes

Components read --bg, --fg and friends, so they work inside any data-theme section unless a spec says otherwise.

Starter code

Components marked React starter ship as .tsx files in files/components, typed and built on the theme. Copy them into the app.

Anatomy

Numbered outlines mark each part of a component; the list beside it names the part and its token.

A quieter link to a related page: "Read all insights", "See how funds use Prime".

Spec

Rules

  • Always a real link; never a button styled as a link.

  • One per block, under the content it relates to.

Forms

Text field React starter

  1. Field 8px gap, 360px or full width
  2. Label label style (11px, uppercase), always visible
  3. Input 52px, linen (--field-bg), 1px --field-border, --radius-sm, 17px text
  4. Help / error 13px, --fg-muted or --danger

States

hoverborder --fg at 60%
focus--focus-field border + 4px --focus-ring
error--danger-border, message below in --danger, aria-invalid="true", aria-describedby → message
disabled50% opacity, not focusable
read-onlyno border, --bg-raised fill

Validation

  • Validate on submit; after the first error, re-check live as the person types.
  • Error text says how to fix it, in the field's terms.
  • Set type, autocomplete and inputmode (email for email).
  • Inputs stay linen on every theme so text contrast never changes.

Alert

Inline messages for form and page feedback. New in this guide: built from the role tokens, not in the prototype yet.

You're on the list. We sent a note to you@company.com.
We couldn't add you to the list. Check your connection and try again.
Access is opening in stages. We'll email you when your group opens.
Figures in brackets are placeholders. Real data arrives with the company feed.

Spec

Container--{status}-bg, 1px border in the status colour at 30%, --radius-md, 16px 18px padding
Icon20px, status colour: check, exclamation, clock, info
Text15px; bold first sentence says what happened, second what to do

Rules

  • Errors: role="alert"; confirmations: role="status".
  • Inline next to the thing it's about; no toasts, no auto-dismiss for errors.
  • Never colour alone: icon + text.
Feedback

Loading

  • Skeletons for anything that loads after the page (directory rows, charts, company data): blocks in --fg at 8%, --radius-sm, matching the final layout so nothing shifts.
  • A slow shimmer (1.6s) only when motion is allowed; static otherwise.
  • Buttons use their own loading state; never a full-page spinner.
  • Container gets aria-busy="true"; announce when content arrives if the person asked for it.

Dot field React starter

Move the pointer over the field

Spec

Groundbottle green, canvas at up to 2× device pixel ratio
Grid9px cell, one dot per cell
Dotradius 0.85px, SL Yellow at 21.6%, always visible
PointerGaussian falloff f = e^-(d/200)²: alpha 0.216 + 0.484 × f, up to 70%
Sizefixed; growing sub-pixel dots draws visible rings
Easingpointer follows at 0.12 per frame; fade in 0.08, out 0.03

Rules

  • Behind stats, panels and the Access hero only; never behind body text.
  • Draw only while on screen (IntersectionObserver); pause when the tab is hidden.
  • Reduced motion: draw once, no pointer response.
  • Decorative: aria-hidden="true", pointer-events: none on the canvas (listen on the parent).
  • Mouse only; touch devices get the static field.
